# Решение по технологии интерфейса

Статус: принято 13 августа 2026 года.

## Контекст

Ядро приложения (`TimerEngine`, статистика, настройки, профили, миграции JSON,
расчёт эффектов и single-instance lock) уже не зависит от Tkinter. С Tkinter
связаны композиция окон, уведомления, системный трей, виджет и отрисовка. Цель
миграции — получить профессиональный адаптивный Windows-интерфейс, не создавая
второй таймер и не меняя существующие форматы пользовательских данных.

Целевая среда проекта — Windows 10/11 и Python 3.14.7. Исходная контрольная
точка `7836003aacaff4a071cbad8284826fbc6068dbb8` прошла 95 `unittest`-тестов.

## Рассмотренные варианты

| Вариант | Сильные стороны | Ограничения и риск |
|---|---|---|
| Tkinter/ttk с собственной надстройкой | минимальная миграция, малая поставка | нет полноценной модели скруглений, теней, DPI-aware painting и сложных состояний; большая часть профессиональных компонентов уже требует ручного `Canvas` |
| PySide6 + Qt Widgets | зрелые Windows-окна, layout-система, QSS, accessibility, high-DPI, `QPainter`, `QPropertyAnimation`, `QSystemTrayIcon`, `QtTest`, надёжная упаковка PyInstaller | поставка заметно больше Tkinter; требуется миграция всего UI-слоя |
| PySide6 + QML/Qt Quick | наиболее гибкие декларативные анимации и визуальные сцены | две технологии и мост Python/QML усложняют семь небольших окон, формы настроек, тесты и сопровождение; часть Quick-модулей повышает лицензионный и сборочный риск без пользы для этого приложения |
| CustomTkinter/ttkbootstrap | быстрый косметический результат и MIT-лицензия | сохраняются ограничения Tk/Tcl, неоднородная доступность стандартных контролов и меньшая гибкость для кольца, эффектов и масштабирования |
| Web-wrapper/Flet | гибкая вёрстка | отдельный runtime, тяжёлый запуск, менее естественные tray/topmost/opacity окна и неоправданная сложность portable-сборки |

## Решение

Интерфейс переносится на **PySide6 6.11.1 и Qt Widgets**. Устанавливается
минимальный пакет `PySide6-Essentials==6.11.1`, который содержит необходимые
`QtCore`, `QtGui`, `QtWidgets`, `QtSvg` и `QtTest`, но не затягивает набор
неиспользуемых Qt Addons. Он официально поддерживает Python 3.10–3.14 и имеет
готовое Windows x86-64 wheel.

Qt Widgets выбран вместо QML: приложение состоит преимущественно из форм,
карточек, таблиц, диалогов и семи компактных окон. `QPainter` и управляемый
общий кадр `OverrunVisualController` покрывают нужные эффекты без отдельной
декларативной среды. Такой стек проще тестировать через `QtTest`, проще
упаковывать и позволяет сохранить существующую Python-композицию сервисов.

Системный трей переводится с `pystray`/Pillow на `QSystemTrayIcon`. После
миграции эти две runtime-зависимости удаляются. Нативные системные сообщения до
создания `QApplication` остаются в `app.single_instance`.

## Лицензии и распространение

- `PySide6-Essentials 6.11.1` и используемые Qt-модули доступны по LGPL-3.0;
  GPL-only модули в проект не импортируются. Onedir-сборка сохраняет отдельные
  Qt DLL и плагины, то есть динамическую компоновку.
- В поставку добавляются тексты лицензии/уведомлений Qt и ссылка на исходники
  соответствующей версии. Это не является юридической консультацией; перед
  публичным коммерческим выпуском владелец проекта должен повторно проверить
  требования LGPL для своего способа распространения.
- Интерфейсные SVG-иконки созданы для проекта и переданы под CC0-1.0. Они
  поставляются как отдельные ресурсы и не заменяют текстовые подписи действий.
- `PyInstaller==6.22.0` остаётся инструментом сборки. Он поддерживает Python
  3.14 и содержит hooks для PySide6.

Первичные источники:

- Qt for Python: https://doc.qt.io/qtforpython-6/
- состав Essentials: https://pypi.org/project/PySide6-Essentials/6.11.1/
- лицензирование Qt: https://doc.qt.io/qt-6/licensing.html
- PyInstaller changelog: https://pyinstaller.org/en/stable/CHANGES.html

## Последствия

- Модели и JSON остаются совместимыми; UI не пишет новые пользовательские
  форматы только из-за смены toolkit.
- У приложения остаются один `QApplication`, один `TimerEngine`, один секундный
  `QTimer`, один `WidgetWindow` и один контроллер эффекта превышения.
- Все размеры интерфейса задаются токенами дизайн-системы в логических пикселях;
  масштабирование выполняет Qt.
- Старый Tkinter UI удаляется после прохождения тестов функционального
  соответствия, чтобы в проекте не осталось двух параллельных интерфейсов.
- Ожидаемая цена решения — больший размер portable-папки и более медленный
  холодный запуск по сравнению с Tkinter. Это принимается ради качества,
  доступности и долгосрочной сопровождаемости Windows UI.
