# Архитектура интерфейса Qt

## Граница с ядром

Интерфейс построен на PySide6 Qt Widgets. `TimerEngine`, модели, статистика, профили, JSON-миграции, расчёт кадров превышения и Windows mutex не импортируют Qt. Единственный `TimerEngine` создаёт `MainWindow`; главное окно, уведомление и `WidgetWindow` получают ссылки на него или на общие команды.

`main.py` сначала получает mutex и только затем импортирует `MainWindow`. `MainWindow` создаёт единственный `QApplication`, один секундный `QTimer`, один `OverrunVisualController`, один `QSystemTrayIcon` и один лениво показываемый `WidgetShell`.

## Модули

- `app/ui/qt_app.py` — создание `QApplication`, адаптер одноразовых `QTimer` и debounce.
- `app/window_geometry.py` — чистая нормализация и возврат главного окна в доступную область экранов.
- `app/ui/design_system.py` — типографика Segoe UI, интервалы, радиусы, размеры, длительности движения, тени и общий QSS.
- `app/ui/components.py` — карточки, кнопки, `ToggleSwitch`, строки переключателей, заголовки, метрики и цветовые образцы.
- `app/ui/icons.py`, `assets/icons/` — проектные CC0 SVG, которые окрашиваются ролью активной темы.
- `app/theme.py` — палитры, валидация пользовательских цветов, глобальный QSS и слабые подписки custom-компонентов.
- `app/ui/timer_visual.py` — крупное время и векторная отрисовка эффектов; собственного цикла не имеет.
- `app/ui/main_window.py` — навигация, команды, синхронизация таймера/статистики/уведомлений/виджета.
- `app/ui/settings_window.py`, `theme_editor.py`, `stats_view.py`, `help_window.py` — страницы приложения и диалог редактора.
- `app/ui/widget_window.py` — одно окно и фабрика семи представлений.
- `app/notifications.py`, `app/ui/tray.py` — Qt-уведомление и системный трей без дополнительных потоков.

## Потоки состояния

Команда пользователя → метод `MainWindow` → `TimerEngine` → статистика при наличии завершённого события → `_refresh_labels()` → `TimerVisual` и текущий `WidgetView`. Виджет вызывает те же методы через `WidgetActions`; отдельного состояния таймера нет.

Тема хранится только в `AppSettings`. `ThemeManager.apply()` ставит общий QSS и уведомляет зарегистрированные компоненты. Подписки bound-методов слабые: удалённая при смене макета Qt-разметка не удерживается менеджером.

Кадр превышения вычисляет `OverrunVisualController` по `time.monotonic()`. `QtScheduler` предоставляет ему одноразовые `QTimer`; один объект кадра применяется к главному `TimerVisual` и виджету. Секундный тик не создаёт анимационных циклов.

## Дизайн-система

Случайные интерфейсные цвета запрещены: компоненты используют смысловые поля `ThemePalette`. Геометрические токены находятся в `TOKENS`: Segoe UI/Consolas, шкала текста, отступы, радиусы, высоты контролов, двухпиксельный фокус и 170-мс спокойное движение. Командные кнопки имеют варианты `primary`, `secondary`, `ghost`, `danger`; двоичные настройки используют только `SwitchRow`/`ToggleSwitch`.

`AppButton.sizeHint()` измеряет подпись через `QFontMetrics` и добавляет внутренние отступы/иконку. `FlowLayout` переносит целые элементы следующей строкой вместо сжатия текста. `ThemedScrollArea` явно задаёт смысловой фон самому контейнеру, viewport и content widget; поэтому системный цвет `#F0F0F0` не появляется в тёмной теме.

## Адаптивная компоновка и геометрия

Первый размер главного окна — 80% `QScreen.availableGeometry()`, но не больше 1440×960 и не меньше 820×560, если экран это позволяет. `main_window_geometry` хранит `x/y/width/height`; move/resize объединяются debounce 500 мс. При старте и возврате из трея прямоугольник полностью ограничивается доступной областью существующего монитора.

Точки перестроения используют ширину клиентской области:

- от 1200 px — полная боковая навигация 220 px;
- меньше 1200 px — панель 72 px с SVG-иконками, доступными именами и подсказками;
- заголовок страницы переносит actions вниз при ширине меньше 720 px;
- настройки при ширине меньше 820 px заменяют боковой список выпадающим выбором;
- карточки тем и статистики переходят из двух колонок в одну по ширине viewport.

Редактор пользовательской темы ограничивается доступной областью экрана. Только центральная палитра прокручивается; верхняя панель и нижние действия используют `FlowLayout` и остаются видимыми.

## Быстрое применение темы

Глобальный структурный QSS устанавливается один раз. При смене темы `ThemeManager` меняет `QApplication.QPalette`, обновляет только видимые Qt-контролы одним polish-проходом и отправляет один semantic callback custom-painted компонентам. Скрытые страницы не обходятся: они получают polish непосредственно в обработчике навигации перед показом. QSS, SVG/QIcon/QPixmap и прямой QSS меню трея кэшируются.

Контрольное измерение десяти переключений на Windows 10 22H2, Python 3.14 и Qt 6.11 снизилось со среднего 888,0 мс (медиана 891,0; максимум 1080,1) до 48,0 мс (медиана 48,0; максимум 59,8). После трёх серий по 20 переключений количество окон, Qt-виджетов, таймеров и theme-listeners осталось неизменным; эти числа являются диагностикой конкретной машины, а не гарантией времени на любом компьютере.

Меню `QSystemTrayIcon` остаётся обычным `QMenu`, но получает собственные background/text/disabled/selected/separator цвета при каждом изменении темы. Окно меню и actions не пересоздаются.

## Windows identity и иконки

`ensure_application()` до первого окна назначает `PomodoroTimerByAnton.Desktop` через `SetCurrentProcessExplicitAppUserModelID`, затем устанавливает многослойный `app.ico` для `QApplication`. Главное окно, диалоги, уведомление и виджет получают ту же иконку явно; tray использует упрощённый контрастный `tray.svg`. PyInstaller задаёт `app.ico` ресурсу EXE.

На Windows 10/11 `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)` запрашивает у системы соответствующий light/dark-заголовок. Сначала используется attribute 20, затем совместимый 19; вызов повторяется в следующем обороте event loop, когда HWND уже показан. Ошибка или системный отказ безопасно оставляет нативный заголовок. На контрольной Windows 10 build 19045 DWM принимал attribute 20, но продолжал рисовать светлую строку — это намеренный системный fallback; приложение не заменяет рамку самодельной. Для виджета первый DWM-вызов выполняется после окончательных window flags и geometry, чтобы не сдвигать сохранённые координаты.

## Жизненный цикл

Закрытие главного окна либо скрывает его в трей, либо вызывает `exit_app()`. Полный выход сохраняет накопленное превышение, останавливает секундный таймер, уведомление, контроллер кадров и все scheduler-таймеры, удаляет виджет и трей, затем завершает `QApplication`. Крестик виджета только скрывает окно и меняет `widget_enabled` через общий обработчик.

## Добавление UI-функции

Сначала расширьте независимую модель/сервис и его тесты. Затем добавьте один адаптер в `MainWindow`; повторно используйте компоненты и токены. Для нового векторного значка добавьте SVG в `assets/icons`, укажите CC0-совместимое происхождение и включите ресурс в spec. Не создавайте дополнительный `QApplication`, периодический таймер или копию состояния.
