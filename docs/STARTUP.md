# Запуск и единственный экземпляр

## Порядок запуска

`main.py` импортирует только модуль `app.single_instance`, получает системную блокировку и лишь затем импортирует `app.ui.main_window.MainWindow`. Поэтому второй процесс не создаёт `QApplication`, не загружает пользовательские настройки, не запускает трей и не выполняет продолжительную инициализацию.

Порядок первого экземпляра:

```text
main.py → SingleInstanceLock.acquire()
        → import MainWindow
        → MainWindow()
        → MainWindow.run()
        → finally: SingleInstanceLock.release()
```

`main()` возвращает код `0` после нормальной работы или обнаружения уже существующего экземпляра. Ошибка создания mutex показывается явно и возвращает код `1`.

## Windows mutex

`app/single_instance.py` использует только стандартный `ctypes`:

- имя имеет вид `Local\PomodoroTimerByAnton.SingleInstance.<user-hash>`;
- хеш строится из домена, имени и домашнего каталога текущего пользователя;
- `CreateMutexW` создает или открывает kernel object;
- `ERROR_ALREADY_EXISTS` означает, что интерфейс запускать нельзя;
- первый процесс удерживает handle до завершения `MainWindow.run()`;
- `CloseHandle` освобождает mutex при нормальном выходе;
- при аварийном завершении Windows автоматически закрывает handle, поэтому постоянного файла или зависшей PID-блокировки нет.

Второй процесс показывает нативный `MessageBoxW` до создания Qt GUI с текстом:

> Pomodoro Timer уже запускается или уже запущен. Дождитесь открытия окна либо используйте уже открытое приложение.

Сложного IPC и попытки поднять существующее окно нет. Ошибки WinAPI не интерпретируются как отсутствие первого экземпляра: они превращаются в `SingleInstanceError` и показываются как ошибка.

Проект фактически ориентирован на Windows (`winreg`, Windows-трей и автозапуск). На другой ОС `SingleInstanceLock.acquire()` явно сообщает о неподдерживаемой системной блокировке, а не разрешает второй экземпляр молча.

## Тестирование

`tests/test_single_instance.py` не создаёт `QApplication`:

- подменяет lock и фабрику окна для проверки раннего выхода;
- проверяет настоящий именованный mutex в Windows;
- запускает дочерний Python-процесс, подтверждает блокировку второго владельца, принудительно завершает первый и проверяет повторное получение mutex.

Обычный запуск и Qt-сборка:

```powershell
python main.py
python -m unittest tests.test_single_instance -v
python -m PyInstaller --noconfirm --clean PomodoroTimerByAnton.spec
```
