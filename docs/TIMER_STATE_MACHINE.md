# Машина состояний таймера

Окончательный источник истины — `app/timer_engine.py`, обработчики `app/ui/main_window.py` и тесты в `tests/`.

## Данные состояния

`TimerState` хранит текущий `mode`, остаток `remaining_seconds`, признак `is_running` и число завершенных рабочих периодов. Для ручного перехода дополнительно используются:

- `waiting_for_continue` — закончившийся период зафиксирован, но следующий еще не начат;
- `overrun_mode` — тип закончившегося периода;
- `overrun_seconds` — прямой отсчет от нуля;
- `next_mode` — режим, который будет запущен после продолжения.

Во время превышения `mode` по-прежнему равен завершенному режиму. Это не позволяет следующему периоду начаться или попасть в статистику раньше времени.

## Состояния и переходы

| Состояние | Отображение | Тики и разрешенные переходы |
|---|---|---|
| Остановлен | `Работа`, полная длительность | `Старт` → работа |
| Работа | `Работа`, обратный отсчет | пауза; пропуск → отдых; `00:00` → автоматический отдых или переработка |
| Короткий отдых | `Короткий отдых` | пауза; пропуск → работа; `00:00` → автоматическая работа или короткий отдых сверх нормы |
| Длинный отдых | `Длинный отдых` | пауза; пропуск → работа; `00:00` → автоматическая работа или длинный отдых сверх нормы |
| Пауза | режим не меняется, время заморожено | `Продолжить` на кнопке паузы → тот же обычный период |
| Переработка | `Переработка`, `+HH:MM:SS`/`+MM:SS` | только явное продолжение → выбранный отдых |
| Короткий отдых сверх нормы | одноименное название и `+…` | только явное продолжение → работа |
| Длинный отдых сверх нормы | одноименное название и `+…` | только явное продолжение → работа |

После завершения рабочего периода счетчик `completed_work_periods` увеличивается на граничном тике. Если включен длинный отдых и счетчик кратен `long_break_interval`, следующий режим — длинный отдых; иначе короткий. Пропущенная работа счетчик не увеличивает и всегда ведет к короткому отдыху.

## Автоматический переход

Если `auto_start_next_period=true`, граничный тик:

1. один раз создает `PeriodCompletion`;
2. один раз учитывает завершенный рабочий период для выбора отдыха;
3. сразу заменяет режим и длительность;
4. оставляет `is_running=true`;
5. не включает `waiting_for_continue` и не создает превышение.

`MainWindow` записывает обычное завершение и показывает информационное уведомление. Поля превышений не меняются.

## Ручное ожидание и «Продолжить»

Если `auto_start_next_period=false`, граничный тик:

1. один раз возвращает `PeriodCompletion`; `MainWindow` сразу записывает нормальную длительность завершенного периода;
2. оставляет завершенный `mode` и остаток `0`;
3. сохраняет `overrun_mode` и рассчитанный `next_mode`;
4. включает `waiting_for_continue`; последующие тики увеличивают только `overrun_seconds`;
5. показывает ручное уведомление, если уведомления включены.

Главное окно всегда показывает отдельную кнопку `Продолжить и начать следующий период`. Кнопка уведомления вызывает тот же `MainWindow.continue_manual_transition()`. Обработчик получает превышение из `TimerEngine.continue_to_next_period()`, записывает его, закрывает уведомление, запускает `next_mode` и обновляет главное окно, виджет и статистику. Повторный вызов возвращает `None`, поэтому повторной записи нет.

Крестик уведомления уничтожает только окно. Таймер продолжает считать превышение, а кнопка главного окна остается доступна. Ручное уведомление не закрывается по таймауту. При отключенных уведомлениях popup не создается, но кнопка главного окна работает так же.

## Пауза, пропуск, сброс, настройки и выход

- В обычном периоде пауза замораживает время, пропуск переключает режим без зачета нормального времени, сброс возвращает остановленную работу и записывает счетчик сбросов.
- Во время ручного превышения `Старт`, `Пауза`, `Пропустить период` и `Сброс` отключены в главном окне; защитные методы ядра также игнорируют такие вызовы. Команда `Старт / Пауза` из трея показывает главное окно, но не останавливает превышение. Команда сброса из трея безопасно игнорируется.
- Изменения настроек во время ожидания не сбрасывают состояние. Новые длительности применяются к периоду, который начнется после продолжения.
- Закрытие главного окна в режим трея не завершает приложение: превышение продолжает считаться.
- При полном штатном выходе `finalize_overrun_on_exit()` один раз забирает накопленное превышение, `StatisticsService` сохраняет его, затем останавливаются трей и Tk. Новый период при этом не запускается.
- Аварийное уничтожение процесса не дает выполнить обработчик выхода; незаписанное превышение в таком случае может быть потеряно.

## Моменты записи статистики

| Событие | Записываемые поля |
|---|---|
| Работа дошла до нуля | `work_seconds`, `completed_work_periods` |
| Короткий отдых дошел до нуля | `rest_seconds`, `completed_short_breaks`; при отключенном длинном отдыхе также цикл |
| Длинный отдых дошел до нуля | `rest_seconds`, `completed_long_breaks`, цикл |
| Продолжение после работы / штатный выход | `overwork_seconds` |
| Продолжение после короткого отдыха / штатный выход | `short_break_overrun_seconds` |
| Продолжение после длинного отдыха / штатный выход | `long_break_overrun_seconds` |
| Пропуск обычного периода | `skipped_periods`; длительность не засчитывается |
| Сброс обычного таймера | `timer_resets` |

Обычные `work_seconds` и `rest_seconds` никогда не включают превышение. Статистический JSON не пишется на каждом тике превышения.
